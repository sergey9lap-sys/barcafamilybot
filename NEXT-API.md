# Расширение Barca Family: интерфейс и контракт API

Рабочая ветка: feature/ratings-and-navigation. Существующий формат запросов сохраняем; переход на Go не требует смены UI.

## Разделы

Верхняя навигация: Голосовать · Рейтинги · Мои матчи. В рейтингах переключатель Игроки / Зрители. Управление видно только администраторам. Голосование открывается первым, без выбора раздела.

## Правила

- Оценки 1–5. Матч: среднее по каждому игроку, команда — среднее оценённых игроков. Неоценённые игроки не получают ноль.
- Сезон: показываем среднюю оценку и сумму баллов отдельными показателями. По умолчанию завершённые настоящие матчи. Незавершённые результаты явно помечены как предварительные.
- Зрители: один отправленный бюллетень за настоящий матч = одно участие; повторное сохранение или изменение не добавляет участия. Не требуем оценивать игроков, которых зритель не видел. Тестовые матчи и черновики не учитываются. При равном числе участий одинаковое место. Публично не показываем Telegram ID.
- История содержит только собственные бюллетени пользователя. Доступ к чужим оценкам до отправки своего бюллетеня сохраняет существующее ограничение.
- Срок: по умолчанию 24 часа, администратор выбирает при открытии. Пользователь видит время окончания и оставшееся время. Закрытие определяется сервером, а не часами телефона.
- Ручной состав клуба: добавить, изменить имя/номер/позицию, убрать из активного списка, вернуть. Исторические голоса не удаляются. Состав матча редактируется до открытия; для исправления после начала требуется отдельное согласованное правило, а не незаметное удаление голосов.
- Импорт из внешнего API не должен молча перезаписывать ручные исправления. Нужны источник, время обновления, стабильный внешний ID и явное разрешение конфликтов.

## Запросы

Все запросы используют существующую проверку Telegram; /admin требует серверной проверки роли.

- GET /api/history?season=&competition=&status=all|open|closed — собственные участия, матч, прогресс, отправлен ли бюллетень.
- GET /api/statistics?season=&competition=&from=YYYY-MM-DD&to=YYYY-MM-DD — команда и игроки: average, total, matches, votes. Включаются закрытые настоящие матчи. Границы периода включительно по дате матча.
- Рейтинг за календарный месяц: Mini App передаёт первый и последний день выбранного месяца через `from` и `to` (например, `2026-09-01` и `2026-09-30`). Это не последние 30 дней. Фильтры сезона и турнира применяются одновременно. Средняя и сумма считаются только по матчам выбранного месяца; пустой месяц возвращает пустой список и `null` для средней, без подстановки сезонных итогов. Для бота нужен аналогичный пункт «За месяц» с выбором месяца.
- GET /api/leaderboard?season=&competition= — место, безопасное отображаемое имя, число участий; собственная позиция отдельно. Лимит выдачи и правила приватности фиксируются сервером.
- GET /api/admin/players?includeInactive=true — полный список клуба.
- POST /api/admin/players/:id — name, role, number, active; изменение с аудитом.
- Существующие создание матча, выбор состава, открытие/закрытие остаются совместимыми.

Турниры: Ла Лига, Лига чемпионов, Суперкубок Испании, Кубок Испании; фильтр «Все турниры». Быстрые периоды: сезон, последние 30 дней, последние 90 дней, свой период. Те же статистические фильтры доступны в админке.

## Обновление

Mini App обновляет видимые результаты с интервалом, только пока открыт соответствующий раздел и приложение видно. Запросы не перекрываются. В Telegram обновляется текущая карточка по кнопке; автоматическая рассылка всем проголосовавшим не включается без отдельной договорённости.

## Визуал

Сохраняем фирменный тёмный фон, Manrope, реальные портреты игроков. Цвета из BF4.png: синий #0068FF, красный #F21A41. Исходный логотип без изменения: public/brand-original.png. Отдельные обложки лежат в public/covers/*.png, соответствия разделов — manifest.json. Текст на обложке называет раздел без рекламных слоганов.

## Форматы ответов, которые уже читает интерфейс

Все числовые поля — JSON numbers, а не строки; неизвестная оценка — null. Даты матчей YYYY-MM-DD, временные отметки ISO 8601 с часовым поясом. Ответы авторизованных запросов не кешировать в общем CDN. Ошибка: HTTP 4xx/5xx и {"error":"Понятное сообщение на русском"}. 404/501 у нового раздела показывает «Раздел скоро появится».

GET /api/statistics:
```json
{"matches":8,"team":{"average":4.12,"total":32.96},"provisional":false,"updatedAt":"2026-09-08T18:00:00Z","players":[{"id":"pedri","name":"Педри","photo_path":"/portraits/pedri.jpg","average":4.25,"total":34.0,"matches":8,"votes":1250}]}
```

Средняя — среднее матчевых средних, а не среднее всех голосов сезона: матч с большим количеством зрителей не получает больший вес. total — сумма тех же матчевых средних без промежуточного округления. matches у игрока — число матчей с оценкой. Верхний matches — число матчей с командной оценкой. Интерфейс обновляет этот ответ каждые 30 секунд только в видимом разделе, без перекрытия запросов. Голосование по текущему матчу остаётся на /matches/:id/results со своей предварительной оценкой.

GET /api/leaderboard:
```json
{"me":{"rank":5,"participations":8},"items":[{"name":"Болельщик","rank":5,"participations":8,"isMe":true}]}
```

Пустой season означает всё время. Максимум 100 строк; me возвращать независимо от попадания пользователя в первую сотню. Публичное имя и участие в списке требуют согласованной политики приватности: до её принятия безопасные псевдонимы, не Telegram ID и не username. В интерфейсе имена экранируются. Сервер вычисляет rank с общими местами для равного числа участий.

GET /api/history:
```json
{"items":[{"match":{"id":"abc","opponent":"Валенсия","score":"0:5","played_on":"2026-09-06","season":"2026/27","competition":"Ла Лига","state":"open","closes_at":"2026-09-09T18:00:00Z","demo":0},"submitted":false,"rated":3,"players":16}]}
```

История также может включать текущие матчи без бюллетеня (rated:0): это позволяет начать голосование с этого экрана. Для закрытого матча UI получает собственные оценки через существующий /api/matches/:id. Не выдавать чужие бюллетени. Пока список не разбит на страницы, сервер ограничивает выдачу 100 последними матчами.

GET /api/admin/players?includeInactive=true возвращает массив существующего формата players с дополнительным active:0|1. POST /api/admin/players/:id принимает {name,role,number,active}; после успешного сохранения UI перечитывает список. Не удалять физически игрока или его исторические связи. Добавление игрока и создание матча используют прежние адреса API. Внешний источник и его авторизацию реализует бэкенд-разработчик.

## Подключение оформления Telegram на Go

Бэкенд этого коммита не изменён. Бот-разработчик подключает файлы обложек по public/covers/manifest.json: home → главное меню; mine → свои оценки и выбор игрока для изменения; results → итог матча; season → общий рейтинг игроков; viewers → рейтинг зрителей; history → история; admin → все административные экраны. Портреты на индивидуальных карточках сохраняются.

Отправлять обложку через sendPhoto, затем редактировать ту же карточку через editMessageMedia; кешировать Telegram file_id. Обновлять итог по кнопке «Обновить» без новой копии сообщения. На главном экране и карточках голосования выводить closes_at и время до закрытия. Автоматические рассылки не требуются. Новые команды/кнопки истории и зрителей реализуются на бэкенде по этому контракту.

## Локальный просмотр для дизайна

`node scripts/design-preview.mjs`, затем http://127.0.0.1:3190/?preview=1. Данные явно подписаны как пример и существуют только в памяти браузера. Режим разрешён только на localhost/127.0.0.1 с явным параметром preview=1; на Vercel не включается и не подменяет ошибки настоящего API. API и хранилище бота этим режимом не изменяются.
